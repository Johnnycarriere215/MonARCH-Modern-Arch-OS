# MONARCH.md

Read this first, every session. This is the whole context.

## Session protocol

1. Read this file.
2. Read `PROGRESS.md` — find the first task not marked `DONE`. That's the current task.
3. Read that task's prompt in `docs/04-TASKS.md`. **Only that task.**
4. Build the whole task. Don't ask permission between steps.
5. Check your work against that task's "Done when" list in `PROGRESS.md`. Say honestly what you did and didn't meet.
6. Update `PROGRESS.md`: mark the task `DONE` or `PARTIAL`, fill in Notes, append a line to the Session log.

**Only read files a task names.** Do not explore the repo to get oriented — this file plus `PROGRESS.md` is all the orientation needed. Unprompted exploration burns the human's usage budget before you write a line.

## Keep chat output short

Tokens are the budget this project runs on. Spend them on code and on
`PROGRESS.md`, not on chat.

- **Do not summarise what you just wrote.** The code and the Notes in
  `PROGRESS.md` are the record. A recap in chat is a third copy that nobody reads.
- Reply in a few lines: what got done, what didn't, anything that needs a
  decision. No headers, no bullet-point tours of the design, no restating the
  task back.
- Explain a design choice **in a comment in the file**, where the next session
  will actually find it. Not in chat, where it evaporates.
- Say what failed plainly. Never pad bad news.
- Long-form writing belongs in `docs/` or in a task's Notes. If it is worth more
  than a few lines, it is worth a file.

If you think a locked decision below is wrong: **say so and stop.** Do not quietly engineer around it.

## What this is

MonARCH is a Linux distribution built **directly on Arch Linux**, using Hyprland as the compositor.

It is **not a fork of Omarchy.** It is an independent project that was inspired by Omarchy and borrows some MIT-licensed pieces from it. There is no upstream remote and nothing to merge. Every file in this repo is ours to change without asking anyone.

Where we deliberately borrow from Omarchy (theme schema, config patterns), we credit it and retain the MIT notice on any file copied substantially verbatim. Everything else is written fresh for MonARCH.

## What MonARCH is for

A fast, keyboard-first desktop that does not require a terminal to configure. Windows 11 is full of ads and Copilot. Linux Mint is comfortable but rigid where it matters. Omarchy is fast but deliberately terminal-only.

MonARCH: Omarchy's speed and looks, with a real settings GUI, a first-run wizard, a Windows-like mode, and documentation that generates itself.

Primary use: coding, AI-assisted development, browser-heavy work. Laptop now, desktop later.

| Layer | Choice |
|---|---|
| Base | Arch Linux, x86_64 |
| Compositor | Hyprland |
| Bar | Waybar |
| Launcher | Walker |
| Notifications | Mako |
| Lock | Hyprlock |
| Terminal | Alacritty |
| Shell | Bash + Starship |
| Login | greetd + tuigreet |
| Filesystem | Btrfs + Snapper (bootable snapshots) |

| Encryption | LUKS, on by default, optional in installer |

## Golden rules

1. **The `monarch` CLI is the only thing that writes config.** The GUI shells out to it. Never writes files directly. If GUI and CLI can disagree, the design is wrong.
2. **TOML is the source of truth; app configs are generated.** `keybinds.toml` → `bindings.conf`. Generated files carry a `# GENERATED BY MONARCH — DO NOT EDIT` header.
3. **No new persistent daemons** for anything Hyprland does natively.
4. **Modes are data, not code.** `modes/<name>/` holds config fragments. Never `if mode == "windows"` in a script.
5. **Every behavior change ships a migration** in `migrations/<unix-timestamp>.sh`.
6. **Bash for system code. Tauri for GUI.** No Python or Node in the system layer.
7. **Ship installers, not binaries** for anything not redistributable (Chrome, Spotify, Typora).
8. **Update `PROGRESS.md` at the end of every task.** It is the only record of where the build is.

## Locked decisions

| | |
|---|---|
| Name / CLI | MonARCH / `monarch` |
| Editor | **MonARCH Code** — our own, Tauri + Monaco. VS Code is a one-command installer |
| Browser | Chromium ships; Chrome is a one-click installer |
| AI | Claude Desktop (AUR `claude-desktop`), needs `CLAUDE_USE_WAYLAND=1` and `/dev/kvm` |
| Workspaces | 5 default; `Super+6` creates a 6th on demand, destroyed when empty |
| `GDK_SCALE` | **1** (1080p panel) |
| Launcher key | Bare `Super` tap → Walker, via `bindr = SUPER, SUPER_L` |
| Dropdown terminal | Native special workspace, not pyprland |
| Desktop icons | **Cut.** Do not implement |
| Password | One master password: LUKS + user changed together, LUKS first |
| Encryption | LUKS default on, **recovery key mandatory**, cannot be silently skipped |
| Update channels | `stable` + `dev` |
| GUI v1 panels | Keybinds · Theme · Monitors · Startup Apps · Performance |
| Install path | Phase 1: `bootstrap.sh` on fresh Arch. Phase 3: own ISO |

## Never do

- Never bundle Chrome, Spotify, or Typora binaries in an ISO. Ship installers.
- Never auto-apply an update without a Btrfs snapshot first.
- Never hand-write hotkey docs — generate from `keybinds.toml`.
- Never claim endorsement by Omarchy, Basecamp, or DHH.
- Never copy an Omarchy file substantially verbatim without retaining its MIT notice.
- Never write a wallpaper into the repo without a recorded license.
