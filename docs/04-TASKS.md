## Staying inside usage limits

Running out means waiting for a reset, not paying. Limits refresh on a rolling ~5-hour window with a separate weekly cap.

**1. Model choice is the biggest lever.** Opus burns budget far faster. Most tasks here are transcription, not design.

| Task | Model |
|---|---|
| T1, T2, T4, T5, T7, T8 | **Sonnet** |
| T3, T6, T9, T10, T11 | **Opus** |

**2. One task per session, `/clear` between.** Context accumulates and re-sends every turn.

**3. Full spec up front, hands off.** Mid-flight additions resend everything. Review at the end.

**4. Diffs, not rewrites.** *"Show only changed lines."*

**Realistic rhythm:** two or three Sonnet tasks per window, or one Opus task. Test in the VM while it resets — verification is your real bottleneck.

## T1 — Bootstrap + package manifests · Sonnet

```
Read MONARCH.md.

Build the install path. Target: fresh minimal Arch install with a user
account, Btrfs root, network up. bootstrap.sh takes it to a working
MonARCH desktop.

1. packages/base.packages — one package per line, comments allowed.
   Compositor stack: hyprland, waybar, walker, mako, hyprlock, hypridle,
   xdg-desktop-portal-hyprland, polkit-gnome, qt5/6-wayland
   Terminal + shell: alacritty, bash, starship, tmux
   Core CLI: git, fzf, ripgrep, zoxide, bat, eza, jq, btop, fastfetch
   System: greetd, greetd-tuigreet, snapper, limine, zram-generator,
   pipewire stack, networkmanager, bluez, brightnessctl, playerctl
   Fonts: ttf-jetbrains-mono-nerd, noto-fonts, noto-fonts-emoji
   Utilities: nautilus, wl-clipboard, grim, slurp, imv, mpv

2. packages/optional.packages and packages/aur.packages
   AUR: claude-desktop, github-desktop-bin, visual-studio-code-bin,
   nwg-displays, hyprbars (via hyprpm)

3. bootstrap.sh — `curl -fsSL <url> | bash` entry point:
   - Refuse to run as root; require sudo access
   - Guard: verify Arch, x86_64, Btrfs root, UEFI. Exit with a clear
     message naming what failed
   - Clone repo to ~/.local/share/monarch
   - Source install/*.sh in numbered order
   - Log everything to /var/log/monarch-install.log
   - On failure, print the failing stage and the log path

4. install/ staged scripts, numbered:
   10-preflight.sh   guards, pacman config, keyring
   20-packages.sh    base packages, then AUR via paru
   30-config.sh      deploy config/ to ~/.config
   40-services.sh    greetd, snapper, zram, bluetooth, firewall
   50-finish.sh      summary + reboot prompt

5. bin/monarch — dispatcher:
   `monarch <group> <verb>` → bin/monarch-<group>-<verb>
   `monarch <verb>` → bin/monarch-<verb>
   Bare `monarch` prints grouped help by scanning bin/ — do not hardcode
   Unknown command → nearest-prefix suggestion, exit 1

6. bin/monarch-doctor — paste-ready report: version, kernel, Hyprland
   version, GPU, RAM, disk, mode, theme, channel, failed units, hyprpm status

7. bin/monarch-version, and a root `version` file containing 0.1.0-dev

Bash only, set -euo pipefail, --help on every script.
Idempotent: running bootstrap.sh twice must not break anything.

Output: bootstrap.sh and base.packages only.
```

## T2 — Base config set · Sonnet

```
Read MONARCH.md.

Write MonARCH's Hyprland, Waybar, and Alacritty configuration from scratch.
Do not copy Omarchy's files. Written for MonARCH, informed by what works.

1. config/hypr/hyprland.conf — main entry, sources the rest:
   monitors.conf, input.conf, looknfeel.conf, windows.conf,
   autostart.conf, bindings.conf (generated by T4), monarch.conf

2. config/hypr/monarch.conf:
   - env = GDK_SCALE,1
   - 5 workspace rules; 6th created dynamically
   - Dropdown terminal: special workspace + size/position rules
   - Sensible Intel-graphics defaults

3. config/hypr/looknfeel.conf — the MonARCH look. Rounded corners,
   restrained animations, subtle blur, gaps. Every color as a variable
   sourced from the active theme. Hardcode nothing.

4. config/waybar/config.jsonc + style.css — workspaces, window title,
   clock, tray, network, bluetooth, audio, battery. Stats modules come
   in T5. Colors from the theme.

5. config/alacritty/alacritty.toml — JetBrainsMono Nerd Font, colors
   from theme, sensible scrollback and padding.

6. config/monarch/settings.toml defaults: mode, theme,
   performance_profile, workspace_count, update_channel="stable",
   startup_apps=[]

7. bin/monarch-config-apply — idempotently deploy config/ into ~/.config.
   Never overwrite user edits: if the target differs from what we last
   wrote, back up to <file>.bak and log loudly.

8. bin/monarch-startup-{list,add,remove} — manage exec-once entries in
   autostart.conf. Default set: essentials only.

Output: hyprland.conf, monarch.conf, and monarch-config-apply.
```

## T3 — Theme engine · **Opus**

```
Read MONARCH.md. Real design latitude here.

The theme engine: one colors.toml restyles the entire system.

1. Define the schema in schema/theme.toml with documented fields:
   background, foreground, accent, 16 terminal colors, semantic roles
   (urgent, warning, ok, muted), plus name/author/light-mode flag.
   The schema is inspired by Omarchy's — credit it in a comment.

2. bin/monarch-theme-apply <name> — renders colors.toml into config for
   Hyprland, Hyprlock, Waybar, Alacritty, Mako, Walker, btop, and VS Code,
   then reloads each. Use templates in themes/_templates/, one per app,
   with simple {{variable}} substitution in bash.

3. bin/monarch-theme-{list,current,install,remove}
   install accepts a local dir or a git URL.

4. Ship three themes in themes/: a near-black default, one light, one
   mid-contrast dark. Write the colors yourself — do not copy another
   project's palettes verbatim.

5. Per-theme backgrounds in themes/<name>/backgrounds/.
   bin/monarch-background-{set,next} handles wallpaper.
   Ship NO wallpaper files — a placeholder README in each backgrounds/
   dir noting that every image needs a recorded license.

Adding a new app to the theme system must mean adding one template file
and nothing else. Explain your template approach before writing code.

Output: monarch-theme-apply and the schema.
```

## T4 — Keybinds · Sonnet

```
Read MONARCH.md.

keybinds.toml is the source of truth; bindings.conf is generated.

1. schema/keybinds.toml — the full default keymap. Schema:

   [[bind]]
   id = "close-window"      # stable identifier, never changes
   keys = "SUPER, W"
   action = "killactive"
   dispatcher = "hyprctl"   # hyprctl | exec
   group = "Windows"
   label = "Close window"
   editable = true          # false = GUI won't offer to unbind

   Cover: window management (close, fullscreen, float toggle, focus and
   swap by direction, resize), workspaces 1-6 plus move-to-workspace,
   app launches (terminal, browser, files, editor), system (lock, logout,
   screenshot, volume, brightness), clipboard, and the dropdown terminal.

   Required: `bindr = SUPER, SUPER_L` → walker (bare Super tap).

2. bin/monarch-keys-apply — reads ~/.config/monarch/keybinds.toml (falls
   back to schema), writes config/hypr/bindings.conf with a
   "# GENERATED BY MONARCH — DO NOT EDIT" header, then hyprctl reload.

3. bin/monarch-keys-check — duplicate combos and Hyprland-builtin
   shadowing. Exit 1 with a readable report. -apply calls it first and
   refuses to write on conflict.

4. bin/monarch-keys-list — grouped, aligned. This is what Super+K shows.

5. bin/monarch-keys-reset — restore defaults, with confirmation.

Parse TOML inline in bash; the schema is flat. No Python or Rust dependency.

Output: monarch-keys-apply plus 20 lines of keybinds.toml.
```

## T6 — Mode system · **Opus**

```
Read MONARCH.md. Real design latitude.

Modes are DATA (config fragments), never code branches.

1. modes/{tiling,windows,performance}/ each with hypr.conf,
   waybar-overrides.jsonc, meta.toml (name, description, requires[]).
   - tiling: default, effects on
   - windows: floating default, hyprbars title bars (close/min/max),
     waybar wlr/taskbar module, bar at bottom
   - performance: blur off, animations off, shadows off, rounding 0,
     minimal waybar

2. bin/monarch-mode-set <name> — swap fragments, reload Hyprland and
   Waybar, persist to settings.toml. Reversible, survives reboot.

3. bin/monarch-mode-session <name> — apply for THIS session only without
   changing the saved default. The first-run wizard asks "what now?" and
   "what default?" separately, so both paths are needed.

4. bin/monarch-mode-{current,list}

5. Windows mode:
   - hyprbars via hyprpm. CRITICAL: it compiles against a pinned Hyprland
     version, so Hyprland updates WILL break it. If the plugin fails to
     load, warn clearly and fall back to tiling — never leave a session
     with no title bars and no explanation
   - Minimize = movetoworkspacesilent special:minimized
   - Restore via waybar wlr/taskbar

Explain your fragment-merging approach before writing code.
```

## T7 — Update system · Sonnet

```
Read MONARCH.md.

1. bin/monarch-update-check — poll GitHub Releases API for the newest tag
   on the user's channel, compare to root `version`. Cache in
   ~/.local/state/monarch/update-available for 30 min.
   Unauthenticated GitHub API is 60 req/hr/IP — never poll faster than
   every 30 min. Fail silently on network error; never block the bar.

2. A waybar custom module showing an update icon when available; click
   runs `monarch update`.

3. bin/monarch-update — strict order:
   a. monarch-snapshot create        (Btrfs via snapper — never skip)
   b. git pull on the user's channel
   c. pacman -Syu
   d. monarch-migrate
   e. AUR updates, then orphan cleanup
   f. hyprpm update                  (warn on failure, don't abort)
   g. monarch-config-apply
   h. restart prompt if kernel or Hyprland changed

4. bin/monarch-snapshot {create,list,restore} — snapper wrappers.

5. bin/monarch-channel-set <stable|dev> — switch tracked branch, persist.

6. bin/monarch-migrate — run migrations/*.sh in timestamp order, once
   each, tracked in ~/.local/state/monarch/migrations-run.

Output: monarch-update and monarch-update-check.
```

## T11 — EdgeHop on Wayland · **Opus** · own track

```
Read MONARCH.md.

I maintain EdgeHop, my own Mouse Without Borders alternative sharing
keyboard/mouse between a Windows machine and this Linux machine. It works
on X11 (Mint). I need it on Hyprland/Wayland, shipping as a MonARCH feature.

Source comes separately. First produce a PORTING PLAN — no code:

1. INJECTION — likely already fine. If EdgeHop creates virtual devices via
   /dev/uinput, the compositor consumes them through libinput like real
   hardware and Wayland doesn't care. Confirm that's what it does.

2. CAPTURE — the hard part. X11 allows global pointer grabs; Wayland
   forbids them. Two routes:
   a. EVIOCGRAB on /dev/input/eventX — device-level exclusive grab,
      bypasses the display server, works on X11/Wayland/TTY. Needs the
      user in the `input` group
   b. libei + xdg-desktop-portal RemoteDesktop — sanctioned, but needs
      portal support and prompts for permission
   Recommend one, with reasoning.

3. EDGE DETECTION — `hyprctl cursorpos`, or subscribe to Hyprland's IPC
   socket at $XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/.socket2.sock.
   We have a no-new-daemons rule — justify your pick on cost.

4. CLIPBOARD — replace xclip/xsel with wl-clipboard.

5. MULTI-MONITOR — edge behavior across a 141 PPI internal panel and
   ~92 PPI externals at different scale factors.

Output: markdown plan. No code.
```
